======================================================================
1. PRODUCT SUMMARY
======================================================================

Build "Nexora AI Operations Platform", a production-oriented AI operations
system for automating customer support and internal business workflows.

The platform receives an incoming request from a user or employee, analyzes
intent, decides which processing path to use, retrieves relevant knowledge,
calls tools when required, selects an appropriate model, generates a grounded
response, evaluates confidence, and either returns the answer automatically or
sends the case to a human review queue.

Core use cases:
- Internal knowledge assistant.
- Customer support triage and response generation.
- Policy / procedure lookup.
- Tool/API invocation.
- Escalation of uncertain or high-risk requests.
- Cost/latency/quality tracking across models.
- Evaluation of retrieval and answer quality.

5.2 Intent Classifier
Classes:
- general_knowledge
- internal_policy
- account_or_customer_action
- data_lookup
- high_risk
- unsupported

Use deterministic rules for obvious cases and LLM structured output for ambiguous cases.

Schema:
{
  "intent": "...",
  "risk_level": "low|medium|high",
  "needs_retrieval": true,
  "needs_tools": false,
  "reason": "..."
}

5.3 Model Router
Model registry fields:
- provider
- model_name
- max_context
- estimated_input_cost
- estimated_output_cost
- capability_tags
- priority
- enabled

Routing strategies:
- cheapest_adequate
- quality_first
- latency_first
- explicit_model
- fallback_chain

Example routing:
- classification -> small/cheap model
- grounded response -> medium model
- complex reasoning -> stronger model
- provider failure -> fallback provider/model

Persist selected model, route reason, latency, tokens, estimated cost, retries, errors.

5.4 RAG / Knowledge Base
Required:
- .txt/.md/.pdf upload
- parsing
- chunking
- embeddings
- pgvector storage
- metadata
- semantic retrieval
- optional hybrid keyword component
- optional reranking
- citations

Each chunk stores:
- document_id
- title
- source
- page_number where available
- chunk_index
- content
- embedding
- metadata

Prompt rules:
- answer only from supplied sources where grounding is required
- cite sources
- state when the information is unavailable
- never fabricate policies

5.5 Tool Calling
Implement at least three safe demo tools:
1. get_customer_summary(customer_id)
2. create_support_ticket(title, description, priority)
3. get_service_status(service_name)

Rules:
- Pydantic validation for tool arguments
- log all tool calls
- high-risk tools require approval
- no arbitrary shell execution
- no unrestricted HTTP execution

5.6 Human-in-the-Loop
Escalate when:
- confidence below threshold
- risk_level == high
- weak retrieval evidence
- unsupported action requested
- structured response validation fails

Review record contains original request, generated response, citations,
escalation reason, confidence, model, timestamps, reviewer decision, edited answer.

5.7 Confidence / Validation
Do not present invented LLM confidence as a mathematical truth.
Construct a workflow decision score from:
- retrieval score
- citation count
- answer validation
- tool success
- self-check result
- structured-output validity

Document clearly that this is a decision heuristic.

- Explicit CORS.
- Security headers.
- SECURITY.md threat model.

Threats to document:
- prompt injection
- data exfiltration
- malicious upload
- tool abuse
- model output injection
- sensitive data leakage
