# Evaluation methodology

The versioned synthetic corpus contains 64 generated files. Sixty supported
documents form the benchmark: 20 invoices, 20 bank statements, and 20 customer
applications. Four unsupported documents test unknown routing separately.

Ground truth is stored independently in `data/ground_truth.json`. Each case
records the structured fields, required/numeric field counts, expected review
route, and edge-case tags. Images/PDFs are generated by
`scripts/generate_dataset.py` with a fixed seed.

## Compared configurations

- **Baseline:** native PDF text plus full-page OCR fallback, rule-based classification, and regex extraction.
- **Improved:** per-page hybrid OCR, strict provider output with one schema repair, and expanded deterministic rules.

The evaluator replays both deterministic profiles over the same versioned
ground truth. It records the dataset SHA-256, configuration descriptions,
per-metric values, correctly directed deltas, most-improved cases, and remaining
failures. Runtime artifacts are written under `data/eval_results`.

Metrics:

- Classification accuracy: correct document-type assignments / documents.
- Required-field recall: extracted required fields / ground-truth required fields.
- Field exact match: exact ground-truth matches / evaluated fields.
- Numeric accuracy: values within ±0.02 / evaluated numeric fields.
- Structured-output success: schema-valid outputs / documents.
- Validation detection rate: detected planted issues / planted issues.
- Review-routing accuracy: correct accept/review decisions / documents.
- Average and p95 latency: deterministic end-to-end replay milliseconds.
- Cost: configured estimated provider cost per document.

These results are reproducible regression evidence, not external OCR/model
quality claims. Provider-backed evaluation should add repeated trials,
uncertainty intervals, pinned model snapshots, and failure-rate reporting.
